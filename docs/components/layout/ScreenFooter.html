ScreenFooterThe ScreenFooter component provides a flexible footer that stays at the bottom of the screen with support for various layouts, backgrounds, and keyboard behaviors. It's ideal for forms, checkout flows, and any screen requiring persistent bottom actions.
  • Overview
  • Dev
Use ExamplesThe ScreenFooter can be used in various scenarios depending on the content and action hierarchy. Each layout type serves different use cases and provides different visual emphasis.
Horizontal Layouts

Horizontal layouts are best when screen content is abundant and vertical space is limited. They keep actions compact while maintaining good reachability. Use the layout prop set to ScreenFooterLayouts.HORIZONTAL.

Layout TypeUse CaseExample
Horizontal - Spread
Best for two equally important actions positioned at opposite ends. Common in navigation flows or when presenting contrasting choices.
Horizontal - Stacked Center
Ideal for primary and secondary actions of similar importance that should be grouped together in the center.
Horizontal - With Content
Perfect for checkout or summary screens where you need to display information alongside actions. The footer can accommodate text, prices, or other content elements.
Vertical Layouts

Vertical layouts provide better action prominence and are recommended when a single primary action needs emphasis, or when content can be obscured. Use itemsFit prop with ItemsFit.STRETCH for full-width buttons or ItemsFit.FIT for content-sized buttons.

Layout TypeUse CaseExample
Vertical - Fit
Buttons are sized based on their content. Best for clear action hierarchy with a prominent primary button and a subtle secondary link button.
Vertical - Stretched
Full-width buttons provide maximum tap area and visual prominence. Recommended for forms and high-priority actions where accessibility is crucial.
Background Types

Choose the background type based on your content density and visual hierarchy needs. Set using the backgroundType prop.

Background TypeVisualWhen to Use
Solid
Provides clear separation with a solid background and optional shadow. Best for content-heavy screens where the footer needs to stand out.
Fading
Creates a subtle gradient overlay that doesn't obscure content completely. Ideal for minimal designs or when content should remain partially visible.
Transparent
No background overlay. Use when the screen has minimal content or a solid background color, and separation isn't needed.
Keyboard Behavior

Control how the footer responds to the keyboard using the keyboardBehavior prop. Choose KeyboardBehavior.STICKY to keep it at the bottom, or KeyboardBehavior.HOISTED to move it above the keyboard.

BehaviorDescriptionExample
Sticky
The footer remains at the bottom of the screen even when the keyboard is open. Best for short forms or when the footer actions don't relate to keyboard input.
Hoisted
The footer moves up with the keyboard, staying above it. Recommended for forms where users need immediate access to submit actions while typing.
UsageCode Example
<View flex bg-$backgroundDefault>
  <ScrollView>
    {/* Screen content */}
  </ScrollView>
  <ScreenFooter>
    <Button label="Primary Action" />
    <Button label="Secondary Action" link />
  </ScreenFooter>
</View>
APIThis is the list of additional props for the component

alignment
FooterAlignment
​

Cross-axis alignment [start, center, end]. In vertical layout: controls horizontal position. In horizontal layout: controls vertical position. Default is 'center'

animationDuration
number
​

Duration of the show/hide animation in ms (sending 0 will disable the animation). Default is 200

animationType
ScreenFooterAnimationTypeProp
​

The animation type for showing/hiding the footer [slide, fade, none]. Default is 'slide'

backgroundType
ScreenFooterBackgrounds
​

The background style of the footer [fading, solid, transparent]. Default is 'solid'

containerStyle
StyleProp<ViewStyle>
​

Custom style for the outer container of the footer. Can be used to override zIndex or other container-level properties.

contentContainerStyle
StyleProp<ViewStyle>
​

Custom style for the content container that wraps the footer's children. Can be used to override default padding, gap, or other layout properties.

hideDivider
boolean
​

If true, hides the top divider for solid background. Only applies when backgroundType is 'solid'. Default is false

horizontalAlignment
FooterAlignment
​

Main-axis alignment for horizontal layout only when distribution is STACK [start, center, end]. Default is 'center'

horizontalItemsDistribution
HorizontalItemsDistribution
​

Distribution of items in horizontal layout [stack, spread]. Default is 'spread'

isAndroidEdgeToEdge
boolean
​

Indicates if the device is an Android device that supports edge-to-edge. Defaults to true for Android with version 35 and above, undefined for others.

itemWidth
DimensionValue
​

Fixed width for all items (used with ItemsFit.FIXED)

itemsFit
ItemsFit
​

How items should fit in vertical layout [fit, fixed, stretch]. Default is 'fit'

keyboardBehavior
KeyboardBehavior
​

The footer's keyboard behavior [sticky, hoisted]. Sticky: stays at bottom when keyboard opens. Hoisted: pushed up when keyboard opens. Default is 'sticky'

layout
ScreenFooterLayouts
​

The layout direction of footer items [horizontal, vertical]. Default is 'vertical'

shadow
ScreenFooterShadow
​

Shadow preset for solid background [sh10, sh20, sh30]. Only applies when backgroundType is 'solid'. Default is 'sh20'

useSafeArea
boolean
​

If true, the footer will respect the safe area (add bottom padding). Default is true

visible
boolean
​

If true, the footer is visible. If false, the footer is hidden using the configured animation type. Default is true
